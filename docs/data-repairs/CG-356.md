# Transmission ground miles

HIFLD's layer metadata reports EPSG:3857 (`wkid:102100`, `latestWkid:3857`):
https://services1.arcgis.com/Hp6G80Pky0om7QvQ/arcgis/rest/services/Electric_Power_Transmission_Lines/FeatureServer/0?f=json

Verified 2026-10-07. `Shape__Length` is a projected map length, not degrees
or ground miles. The old multiplier of 69 was invalid. The importer requests
`outSR=4326`; both it and migration 0041 measure that geometry using
`ST_Length(geometry::geography, false) / 1609.344` (PostGIS spherical metres
to international miles). Do not reinterpret the old values with a unit factor.

Migration 0041 creates an empty backup table and makes lengths nullable through
the existing deployment pipeline. The checked-in repair workflow runs the
large backfill outside the Vercel build, after the migration is available. It is
transactional and idempotent; a failed early run must be rerun after deployment. Missing
or empty geometry becomes null, not zero or a fabricated distance. API types and
existing unknown-value displays accept null. The obsolete committed JSON export
is removed; the public API and weekly transmission GeoJSON are the maintained
exports. Tile properties refresh with the normal transmission tile workflow.

Rollback must be a reviewed follow-up migration, not a production console write:

```sql
UPDATE transmission_lines t
SET length_miles = b.length_miles, version = t.version + 1, updated_at = NOW()
FROM transmission_length_repair_0041 b
WHERE t.id = b.id AND t.version = b.version + 1;
```

The version guard prevents reverting later edits. Keep the backup until the
repair is independently verified. Do not restore NOT NULL until all current
rows have real measured lengths. The legacy JSON can be restored from git if
needed, but should not be advertised as accurate data.
